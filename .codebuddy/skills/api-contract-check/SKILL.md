# 接口联动一致性检查

对一次接口变更做全链路核对，输出缺口清单。只读。

## 检查矩阵

| 环节 | 查什么 | 常见缺口 |
| --- | --- | --- |
| Controller | 路径、方法、`@Valid`、返回 `Result` | 缺 `@Valid`、路径与网关不一致 |
| DTO/VO | 字段名、类型、校验、中文提示 | 前端类型与 VO 不一致、可空性不同 |
| 错误码 | 是否在 `ErrorCode`、HTTP 映射是否存在 | 裸数字、前端没处理新码 |
| 网关 | `spring.cloud.gateway.server.webflux.routes` 是否有该前缀；白名单是否需要 | 路由缺失导致 404、白名单过宽 |
| 鉴权 | 是否应要求令牌；`/admin/api/**` 是否要 `role=admin` | 误加白名单 |
| 前端 | `api/types.ts`、`api/*.ts`、页面调用 | 字段拼写、分页参数、baseURL |
| 数据库 | 迁移是否新增、字段与实体一致 | 实体有字段但表没有 |
| 文档 | README 端口/路由表、`docs/contracts/` | 文档停留在旧版本 |
| 测试 | 成功/失败/越权/重复提交 | 只测成功路径 |

## 步骤

1. 用 Grep 定位该接口在前端、网关、后端的全部出现位置（按路径字符串搜）。
2. 逐项填矩阵，缺口标为“阻断/建议”。
3. 输出：`契约现状 → 缺口清单（文件:行号）→ 修复顺序 → 需要谁配合`。

## 判定

- 路径/字段/错误码任一不一致 → 阻断，必须先统一。
- 网关已路由但白名单未加（认证接口）→ 阻断（会 401）。
- 文档不同步 → 建议，随同一次提交修。
